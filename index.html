kh-claude

Claude Code on KeyHelp servers

One command installs Claude Code on a KeyHelp Debian server. It runs as your site user, backs up every file before changing it, and remembers each project between sessions.

# curl -fsSL https://nicvex.github.io/kh-claude/install.sh | bash -s user

Run as root. Replace user with your KeyHelp username.

Get started

  1. Run the install command above on the server.
  2. Start Claude: claude for an overview of all projects, or claude shop.de for one project. Run hash -r first if you installed in the same shell.
  3. On the first start, open the login link in your browser and paste the code back. This needs a Claude Pro, Max, Team, Enterprise or Console account.

What it sets up

Claude Code
Installed from Anthropic's signed apt repository. The key fingerprint is checked before anything is installed.
Never as root
Typing claude as root starts it as the KeyHelp user, inside tmux. Lost your SSH connection? Run claude again and you're back in the same session.
Server context
www/CLAUDE.md tells Claude it's on a KeyHelp server, that every folder is a separate project, and which settings belong in the panel.
Backups outside your projects
Before a file is changed or deleted, the original is copied to claude-backups/. New files are listed so you know what to remove when rolling back.
Project memory
Each project gets a MEMORY.md with structure, notes, open tasks and a changelog. It's loaded when a session starts and updated after each step.
Root-owned files
kh-fixowner gives files inside www/ back to the user. Claude has to ask you every time.
Databases
Claude reads with each project's own credentials. Before any write, it makes a dump and asks.

Folder layout

/home/users/user/www/
├── CLAUDE.md
├── shop.de/                      your project, kept clean
└── claude-backups/
    └── shop.de/
        ├── MEMORY.md             project memory
        ├── 2026-11-18_14-02_abcdef12/
        │   ├── files/            originals before the first change
        │   ├── MANIFEST.txt      every action with time
        │   └── NEW.txt           files Claude created
        └── db/                   dumps before database writes

Everyday commands

claudeStart, or reattach to the running session
claude shop.deStart in one project
Ctrl+b, dDetach. Claude keeps running.
tmux lsList running sessions
/resumeReopen an earlier conversation
kh-claude-updateShow what changed and install a new version

Updates

Every time you start claude, it checks GitHub for a new kh-claude version and tells you. kh-claude-update shows the exact changes and asks before installing. Claude Code itself is upgraded daily from Anthropic's signed repository.

Settings are in /etc/kh-claude.conf:

KH_USER="user"
CLAUDE_AUTO_UPGRADE="yes"   # daily Claude Code upgrade
AUTO_UPDATE="no"            # "yes" installs kh-claude updates automatically

With AUTO_UPDATE="yes", your servers run whatever is published here as root, every day. Leave it off unless you control this repository.

Want a fixed version? Install from a release tag instead:
curl -fsSL https://raw.githubusercontent.com/nicvex/kh-claude/v1.0.1/install.sh | bash -s user

Security model

Claude runs as the KeyHelp user, so it can't reach other users, KeyHelp itself or system files. The only root action available is kh-fixowner, limited to www/. sudo, mysql and mysqldump always ask for permission. There is no KeyHelp API access; the panel stays yours.

Read install.sh before you run it. It's one file.

Uninstall

rm -f /usr/local/sbin/claude /usr/local/bin/claude-kh /usr/local/bin/kh-backup \
      /usr/local/bin/kh-memory /usr/local/bin/kh-claude-update /usr/local/sbin/kh-fixowner \
      /etc/sudoers.d/kh-fixowner /etc/cron.daily/kh-claude /etc/kh-claude.conf
rm -rf /usr/local/share/kh-claude
apt remove claude-code        # optional

Backups, memory files and www/CLAUDE.md stay where they are.
